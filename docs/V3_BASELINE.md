# Deep Research Agent V3 基线说明

## 1. 文档目的

本文记录 V3 在冻结时应当具备的系统边界、技术栈、核心流程和已完成能力。它既是后续 V4 改造的对照基线，也是面试中解释“改造前系统是什么样”的依据。

> 重要说明：本文描述的是当前代码能力，但“V3 已冻结”仍需完成文末的提交、验证、基线评测、Git Tag 和远端推送流程。仅创建本文档不代表版本已经冻结。

## 2. V3 的产品定位

V3 是一个可公开演示的单体 Deep Research Agent。用户输入研究主题后，系统自动规划多个子任务，并行检索网页、总结各子任务，最后生成带来源的 Markdown 研究报告。浏览器通过 SSE 实时看到规划、来源、阶段总结、失败、取消和最终报告。

V3 适合作为作品集演示和 V4 实验 baseline，不定位为多租户、高并发生产平台。

## 3. 技术栈

| 层次 | 技术 | 当前用途 |
|---|---|---|
| 前端 | Vue 3、TypeScript、Vite | 研究表单、任务进度、来源、工具事件、流式总结和报告展示 |
| API | FastAPI、Pydantic、Uvicorn | 请求校验、研究接口、SSE、取消、健康检查和静态资源服务 |
| Agent | HelloAgents `ToolAwareSimpleAgent` | 规划、子任务总结和报告生成 |
| 模型接入 | HelloAgents LLM + OpenAI-compatible API | 支持 Ollama、LM Studio 和自定义兼容端点 |
| 搜索 | DDGS、Tavily、Perplexity、SearXNG | 多搜索后端、降级搜索和网页材料获取 |
| 网络 | HTTPX、Requests | 网页抓取、超时控制、响应大小限制和 URL 安全检查 |
| 并发 | Python Thread、Queue、Lock | 多个研究子任务并行执行及 SSE 事件汇合 |
| 可观测性 | 自研 RunRecorder、InstrumentedLLM | 阶段耗时、任务状态、搜索次数、Token、成本和告警记录 |
| 评测 | Pytest、自研 benchmark runner | 固定题库批跑、引用、来源可访问性、语义支持和运行指标 |
| 部署 | Docker、Render Blueprint | 前后端单容器、单域名部署 |

## 4. V3 系统结构

```text
Browser / Vue
      │
      │ POST /research 或 /research/stream
      ▼
FastAPI
  ├─ 配置校验
  ├─ Basic Auth
  ├─ IP 限流与每日预算
  ├─ job_id 注册与取消信号
  └─ RunRecorder
      │
      ▼
DeepResearchAgent
  ├─ PlanningService
  ├─ Search Service
  ├─ SummarizationService
  ├─ ReportingService
  └─ ToolCallTracker / NoteTool
      │
      ├─ LLM API
      └─ Search API / Public Web
```

前端构建产物由 FastAPI 提供，因此公开演示只需要一个容器和一个访问地址。

## 5. V3 核心执行流程

```text
输入主题
  ↓
一次性生成 TODO 子任务
  ↓
为每个子任务启动并行 worker
  ↓
搜索与网页材料准备
  ↓
生成子任务总结
  ↓
合并所有已完成结果
  ↓
生成最终报告
  ↓
执行引用/来源审计并返回结果
```

非流式接口顺序执行子任务；流式接口使用多个线程并行执行子任务，并通过线程安全队列将事件发送给同一条 SSE 流。

### V3 的流程性质

V3 是“先规划、后执行”的固定工作流。它可以并行处理多个子任务，但不会根据本轮证据的充分程度重新设计研究计划。搜索质量不理想时主要依赖搜索后端内部的降级与补充策略，而不是 Agent 级的 `检查覆盖度 → 重新规划 → 再研究` 循环。

因此，`max_web_research_loops` 不应被表述成完整的自主研究循环；V3 尚未实现基于证据状态的动态停止与补搜决策。

## 6. 已完成能力

### 6.1 研究规划与执行

- 通过 LLM 把主题拆成结构化 TODO 子任务。
- 规划输出无效时，可从工具事件恢复任务或生成单任务 fallback。
- 每个子任务保存标题、意图、查询、状态、总结和来源。
- 流式运行时并行执行多个子任务。
- 单个子任务失败可记录失败状态；搜索无结果可标记为跳过。

### 6.2 实时交互和取消

- SSE 推送 `job`、`status`、`todo_list`、`sources`、`task_summary_chunk`、`task_status`、`tool_call`、`final_report`、`error`、`cancelled` 和 `done` 等事件。
- 前端实时展示任务列表、来源、流式总结、工具轨迹和最终报告。
- 每次运行使用稳定 `job_id`。
- 支持协作式取消；节点或阶段边界会检查取消信号。
- 已经发出的第三方 HTTP/LLM 请求不保证被立即强制中止。

### 6.3 搜索与网页证据准备

- 支持 DDGS、Tavily、Perplexity 和 SearXNG。
- DuckDuckGo 路径包含多引擎适配和有限 fallback。
- 支持正文抓取、内容长度限制和请求超时。
- 对非公开地址等风险目标进行限制，降低 SSRF 风险。
- 对明显无关结果做过滤，并进行域名多样化和来源排序。
- 可补充并优先考虑官方文档、政府或学术来源。

### 6.4 来源追踪与引用质量

- 可为来源生成稳定 `SourceRecord` 编号。
- 可从子任务总结提取 `ClaimMapping`，记录结论与来源编号的关系。
- 报告生成时提供来源目录并限制模型使用不存在的来源编号。
- 可把内部来源编号渲染为最终报告中的可点击引用。
- 对报告执行来源编号完整性、URL 对应关系、引用覆盖率和来源相关性审计。
- 报告不完整或引用质量较差时支持一次受控重写；失败时保留原报告或确定性 fallback。

这套能力已经构成 Evidence Store 的雏形，但 V3 还没有独立的一等 `Evidence` 对象，不能完整表示“哪个网页片段支持、反驳或补充哪个子问题”。

### 6.5 可观测性和成本

- 记录规划、搜索、总结、报告等阶段耗时。
- 记录任务数量和每个任务的终态。
- 记录搜索调用、LLM 调用和 Token usage。
- 配置价格表后可计算费用；无法可靠获得 usage 时明确标记 unavailable 或 estimated。
- 成功、失败和取消后可将单次运行指标原子写入 JSON。
- 评测请求可选择通过 SSE 接收 metrics 事件，普通前端协议不受影响。

### 6.6 自动评测

- 版本化 20 题题库，包含事实、比较、多来源、冲突、证据不足、安全、时效性和跨语言场景。
- 支持按题号、类别和标签筛选。
- 支持分批执行、超时取消、单题失败继续、断点续跑和只重跑失败项。
- 汇总成功率、耗时 P50/P95、引用数量、独立域名、引用覆盖率和来源可访问率等指标。
- 支持导出结论—引用人工复核材料，并区分严格/宽松语义支持率。
- 支持 A/B 请求参数，例如来源追踪开关和研究深度。

### 6.7 部署保护

- 单 Docker 容器同时承载前端和后端。
- `/healthz` 检查进程存活，`/readyz` 检查关键配置和剩余额度。
- 可配置 Basic Auth、IP 窗口限流和实例每日研究预算。
- 密钥通过环境变量提供，不写入镜像。

## 7. V3 已知边界

- 没有 Agent 级 Coverage Checker。
- 没有基于证据不足、来源冲突或信息增益的 Replan。
- 没有明确的 Evidence 数据模型和任务级 Evidence Store。
- 没有单次研究的持久化 checkpoint/resume；评测 runner 的 `--resume` 不能替代它。
- 运行状态、取消信号和限流计数保存在单进程内存中，容器重启后丢失。
- 当前并发采用线程，缺少统一的任务级并发上限、重试、指数退避和部分失败策略。
- 自研 telemetry 能记录指标，但还没有完整呈现每次路由判断前后的状态差异。
- 前端显示任务进度，但尚未突出展示“为什么补搜、为什么停止”。

## 8. V3 冻结验收清单

冻结时应创建一个不可漂移的 Git 基线：

1. 明确当前工作区中哪些改动属于 V3，并全部提交。
2. 记录冻结提交的 commit SHA。
3. 运行后端测试、前端构建和 Docker 构建。
4. 使用固定模型、搜索后端和配置运行 V3 基线题集。
5. 保存机器可读评测产物和一份人类可读基线报告。
6. 记录必要环境变量名称、模型名称、搜索后端和题库版本；不保存密钥值。
7. 创建 annotated tag，例如 `v3.0.0`。
8. 将 V3 commit 和 tag 推送到 GitHub。
9. 后续 V4 开发从新分支开始，禁止移动或覆盖 `v3.0.0` tag。

冻结的完整定义是：

```text
代码 commit
+ Git tag
+ 可复现配置
+ 自动测试结果
+ 固定题库基线
+ 已知问题
```

## 9. V3 在面试中的准确表述

可以表述为：

> V3 已经完成一个可部署的端到端 Deep Research 系统，包括任务规划、并行检索、流式进度、取消、搜索降级、来源追踪、引用评测和成本观测。它的限制是研究计划在执行后基本不再变化，尚不能根据证据充分性主动补搜，也不能从单次研究的持久化 checkpoint 恢复。因此我把 V3 固定为 baseline，在 V4 中重点改造研究决策与状态编排，而不是重写已有产品外壳。
