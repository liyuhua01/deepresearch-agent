# 来源追踪单题 A/B 预发布验收（2026-08-07）

## 实验设置

- 环境：独立 Render 预发布服务 `deepresearch-agent-phase-a-staging`
- 固定题目：比较 Python `asyncio` 与 `ThreadPoolExecutor` 在高并发网络 I/O 场景下的适用性、性能瓶颈、错误处理方式和工程选型建议，并引用 Python 官方文档及可靠技术资料。
- A 组：`enable_source_provenance=false`
- B 组：`enable_source_provenance=true`
- 两组使用相同的模型、搜索后端、非流式 `/research` 接口和 600 秒客户端超时。
- B 组通过单次请求实验开关启用；部署默认值仍为 `false`。

## 质量观察

B 组的报告层引用约束确实生效：引用被放在事实性结论附近，最终覆盖率由 31.37% 提升到 80%，且 5 个报告 URL 全部来自过程来源目录。

但 B 组尚不能通过完整来源追踪验收：

1. 总结器返回了 `DSML TOOL_CALL` 包装内容，过程映射器把两个包装标签识别为结论，真实结论没有形成映射，因此 `mapped_claim_count=0`。
2. 43 次引用仅来自 5 个唯一 URL，平均每个 URL 被引用 8.6 次；覆盖率提高部分来自重复粘贴相同来源，不能等同于引用支持率提高。
3. 搜索结果包含 OpenAI Agents SDK、`uv` 包管理博客等与核心比较关联较弱的来源；报告虽然主动标记其中一个低相关来源，但仍使用了部分弱证据。
4. B 只有 1 个子任务、A 有 5 个子任务，说明模型规划存在显著随机性。本次耗时下降 84.29% 只能作为观察值，不能作为性能成果写入简历。

## 验收判定

- 工程兼容性：通过。两组均完成，旧请求默认行为不变。
- 来源目录与报告链接约束：通过。
- 报告层结论引用覆盖：初步通过，80% 达到可继续优化的水平。
- 过程层结论—来源映射：未通过，当前有效映射为 0%。
- 引用相关性与支持关系：未通过自动验收，仍需修复后抽样人工核查。
- 性能结论：证据不足，至少需要多题、多次重复后报告 P50/P95。
- 默认上线：暂不建议；保持 `ENABLE_SOURCE_PROVENANCE=false`。

## 下一轮修复门

1. 在提取映射前解析总结器的工具调用结果，禁止把 DSML/JSON 包装标签当作结论。
2. 校验来源编号与其 URL 是否准确配对，区分未知、未链接和 URL 不匹配三种错误。
3. 增加重复引用率和单一来源集中度指标，避免靠重复链接抬高覆盖率。
4. 对搜索结果增加主题相关性检查，优先 Python 官方稳定版文档，过滤明显离题来源。
5. 修复后至少运行 8 道固定题；每题建议重复 3 次，再比较完成率、覆盖率、来源支持率及 P50/P95 耗时。

B3 真实输出已不含 DSML/JSON 残留。最初在线审计报告 7 个裸编号；复核发现它们全部来自“已忽略 T1-S4/T1-S5、来源覆盖说明”等来源质量元数据，而非事实结论。最新确定性规则对同一份 B3 原始输出回放后，裸编号降为 0，得到 20 条真实结论、8 条有效严格映射。

修复轮判定：

- 总结工具包装清洗：通过。
- 编号—URL 严格配对：通过，未知和错配均为 0。
- 来源质量风险识别：通过，能标记 3/5 弱相关来源且报告明确忽略其中两项。
- 过程映射完整度：仍不足，最新单次为 40%。
- 报告引用质量：仍不足，重复引用率 84.38%，且唯一来源仅 5 个。
- 默认上线：仍保持关闭。下一阶段重点应从解析器转向搜索召回质量、官方来源优先级和重复引用约束。

B6 修复后，3 个目录来源全部为 `docs.python.org` 官方文档，3 个报告 URL 现场检查均返回 HTTP 200，相关性待复核数与过程映射错误均为 0。这说明离题来源故障已在该真实样本上修复。

但 B6 仍不足以支持默认开启：来源集中于单一域名，且更偏向 `asyncio` 文档；重复引用率 76.92%，质量重写两次都因未达改善门槛而正确保留原报告。下一个正式门槛仍是固定 8 题批量评测，而不是继续对单题追加结论。
