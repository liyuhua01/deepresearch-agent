## V3 失败案例：Q16

Q16 主题：

> 截至评测执行日期，对比主要模型提供商公开文档中的上下文窗口、输入输出价格和缓存计费，并记录资料更新时间。

运行结果：

```text
status: completed
benchmark_success: false
duration: 83.50 秒
unique citations: 0
claim citation coverage: 0
failure_stage: null
```

这说明 V3 的“运行成功”和“研究质量达标”必须分开：该题完成了流程并生成报告，但没有形成可验证引用，因此不能算 benchmark success。

该案例直接暴露 V4 应解决的问题：

1. 报告前缺少硬性的 Evidence/Coverage gate。
2. 系统发现零引用时没有回到搜索或证据抽取阶段补救。
3. `failure_stage` 只适合记录运行故障，尚不能表达质量失败原因。
4. 时效性和模型定价类问题需要更明确的官方来源要求与更新时间字段。

V4 应将其归入类似 `insufficient_coverage` 或 `missing_authoritative_evidence` 的质量失败类别，并用 `Coverage Checker → Replan` 尝试修复。

## 其他需要进入 V4 的边界

- Q01 的 claim citation coverage 只有 34.78%，虽然达到当前整体 benchmark success 条件，仍属于低覆盖样本。
- Q10 的 claim citation coverage 为 15.79%，cited source relevance 为 7.14%，说明“有引用”不等于“来源与结论相关”。
- Q19、Q20 的 cited source relevance 分别为 50% 和 48%，适合进入来源质量和补搜策略回归集。
- Q17 耗时 227.34 秒，是本次最长样本，可用于 V4 的时间预算和停止条件测试。
- 整体引用可访问率 65.32%，低于历史演示建议的 80%，应保留为 V3 已知质量缺口。
- 每题只运行一次，当前数据不能用于声称稳定 P50/P95，也不能消除公开搜索随时间波动的影响。

## 使用限制

对外可准确表述为：

> V3 在一次真实 20 题评测中 20/20 完成，19/20 达到自动成功标准；加权结论引用覆盖率为 75.76%。单次样本同时暴露了零引用、低来源相关性、引用可访问率不足和长尾延迟问题，这些问题将作为 V4 Evidence、Coverage 和 Replan 设计的固定回归案例。

不得表述为：

- “V3 有稳定 95% 成功率”；
- “P95 稳定为 182 秒”；
- “引用语义正确率为 82.58%”；
- “20 题全部质量达标”。

原因是本轮只有一次重复，`source relevance` 也不等同于经过独立人工复核的 citation semantic support。
